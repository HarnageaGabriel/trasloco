# Azure Pipelines resolved AST normalization

Status: draft for approval (M1). Normative for `internal/dialect/azurepipelines/normalize`.

Normalization accepts an `ast.Pipeline` after template expansion. `extends`, template references, and `${{ }}` directives are errors (`TRL-CONV-0010`, `ErrNeedsResolver`), which acts as a guard for callers that skip the resolver. Runtime `$[ ]` expressions remain deferred. Provider macros are classified against declarations visible at the use site (parameters/inputs and pipeline, stage, job or step variables, using the scope rules in [variable-precedence.md](variable-precedence.md)); no macro value is evaluated and no external/UI/group members are invented. Normalization performs no I/O.

Every source-derived IR node carries its AST source position and a SHA-256 source-span hash. Synthetic default stages, jobs, checkout, and deployment artifact downloads are explicitly identifiable and may omit an origin as allowed by ADR 0003. Unsupported fields are retained under `extensions.x-azure-pipelines.losses` and reported with `TRL-CONV-0008`; deferred `$[runtime]` text is kept literal under `extensions.x-azure-pipelines.deferred`, with info `TRL-CONV-0009`. Whole-value macros become `Expr{kind: macro, macro: MacroExpr}` and text-embedded run macros become `RunStep.macroRefs`; original spellings are preserved. An unresolved macro records `TRL-CONV-0009` without inferring a secret; cross-dialect emission requires manual handling (VERIFY-22). These T1 contracts are prerequisites for the later reader implementation; no implementation or corpus update is part of T1.

## Default and macro normalization rules

- Repository context is `Options.RepositoryType`: `github`, `bitbucket`, `azureReposGit`, `other`, or `unknown` (including the zero value). The caller supplies it; the normalizer does not inspect remotes. Omitted `pr` synthesizes an unfiltered PR trigger for GitHub/Bitbucket; Azure Repos Git gets none and records `TRL-CONV-0004` explaining branch-policy ownership. `other`/`unknown` synthesize with `fidelity: approximated`. Explicit `pr: none` prevents synthesis. All synthesized defaults use `binding: {inYaml: false, synthetic: true}` and `TRL-CONV-0004`. Sources: [GitHub](https://learn.microsoft.com/en-us/azure/devops/pipelines/repos/github), [PR schema](https://learn.microsoft.com/en-us/azure/devops/pipelines/yaml-schema/pr).
- Glob translation preserves `original`, signs, escapes, `?`, and classes. Unescaped star runs normalize idempotently to `**`; includes precede excludes. Exclude-only filters gain a leading `**` with `TRL-CONV-0004`. The possible star widening is marked `fidelity: approximated` with `TRL-CONV-0001` (VERIFY-01: fire more often, never less). Sources: [trigger](https://learn.microsoft.com/en-us/azure/devops/pipelines/yaml-schema/trigger), [pr](https://learn.microsoft.com/en-us/azure/devops/pipelines/yaml-schema/pr).
- Pool inheritance is resolved before runner, shell and timeout defaults. Only absence at **every** applicable level (pipeline, stage, job, deployment hook) materializes `RunnerReq.image: ubuntu-latest` and `RunnerReq.os: linux` with synthetic metadata and `TRL-CONV-0004`. A named self-hosted pool is never defaulted. Existing `image` values map to `os` through a shared documented Microsoft-hosted image table; unknown `arch` stays absent. Sources: [Hosted agents](https://learn.microsoft.com/en-us/azure/devops/pipelines/agents/hosted), [Pools](https://learn.microsoft.com/en-us/azure/devops/pipelines/agents/pools-queues).
- Whole-value macros in variable values, step env, task inputs and checkout refs become `MacroExpr`, except the portable `refSource: sourceVersion` checkout default. `RunStep.macroRefs` contains a flat `MacroRef{name, declared, secret}` for each macro occurrence in `script` then `workingDirectory`, including duplicates, in textual order. The reader conservatively recognizes `$(NAME)` where `NAME` matches `[A-Za-z_][A-Za-z0-9_.-]*`; an undeclared simple name such as `$(date)` remains unresolved (VERIFY-22), not inferred to be shell substitution or a secret. Other `$(...)` text is retained without inventing a macro. Scope resolution classifies only declarations actually present; imported variable-group members and predefined names without declarations stay unresolved. A declared secret resolves to a `SecretRef`; declared non-secrets have `declared: true, secret: false`; unresolved references have both false and `TRL-CONV-0009`. No macro values or secret values are expanded. Sources: [Variables](https://learn.microsoft.com/en-us/azure/devops/pipelines/process/variables), [Secret variables](https://learn.microsoft.com/en-us/azure/devops/pipelines/process/set-secret-variables).

## Resolver integration

- The corpus golden test parses each positive fixture, runs `resolve.Resolve` over a `localfs` source rooted at the corpus (aliases `common` and `scans` map to `_repos/templates-common` and `_repos/security-scans`) and normalizes the resolved AST. Fixtures whose resolution reports error diagnostics are pinned in the test (`resolveFailures`, with codes and reason) and get no golden; the test asserts the normalized and pinned counts so a fixture can never be skipped silently. The determinism check re-parses and re-resolves.
- Provenance: `ir.Origin.Chain` is copied from `ast.Pos.Chain` (template call sites, outermost first, ADR 0003) for every node that carries an origin, including raw nodes and opaque conditions. `Options.SourceChain`, when set, overrides the AST chain.

## Verification notes

- VERIFY-01: Azure `*` matching `/` remains unconfirmed; the reader widens to IR `**`, marks approximation, and retains the emit-gha VERIFY-01 item.
- VERIFY-12: the 60-minute Microsoft-hosted agent-job timeout is not confirmed by the current [Jobs page](https://learn.microsoft.com/en-us/azure/devops/pipelines/process/phases). Materialize `Job.timeout: 1h0m0s` only for omitted hosted-job timeouts, synthetic and approximated; keep self-hosted/unknown defaults unset with a loss. The emitter carries this fidelity. Agentless jobs are not evidence for the hosted-agent default.
- VERIFY-22: Azure's undefined-macro behavior remains unconfirmed. Preserve spelling and unresolved classification; cross-dialect emission uses a manual placeholder or diagnosed dropped variable, never an inferred secret.

- VERIFY-07: Azure Bash invocation defaults remain unconfirmed. Explicit Bash and generic `script:` resolved to Bash carry `shellOptions: {errexit: false, pipefail: false}`. Generic `script:` resolves only from a documented Microsoft-hosted image (`windows` -> `cmd`, `linux`/`macos` -> `bash`); a named self-hosted pool or unknown image retains `azure-default` with a loss. See [Script steps](https://learn.microsoft.com/en-us/azure/devops/pipelines/yaml-schema/steps-script), [Bash steps](https://learn.microsoft.com/en-us/azure/devops/pipelines/yaml-schema/steps-bash), and emit-gha VERIFY-07.
- VERIFY: repository-resource trigger identity has no dedicated field in the current IR trigger model. It is retained in the ID and pipeline extension; a future IR resource reference would be safer than relying on identity spelling.
- VERIFY: variable-group imports are represented without expanding group members. A dedicated group-reference IR node would distinguish the import from an ordinary variable more cleanly.
- Parameters: the default literal is built from the declared type; a default that does not fit (for example a non-boolean for `boolean`, or a structured value) is dropped with a loss.
- Secrets: literal values under secret-looking keys (variables, step env, task inputs, container env, extension subtrees) become `SecretRef`/secret references or `[REDACTED]`; credential patterns are scrubbed by `internal/redact`. Inline script text is scrubbed of credential patterns, and replaced as a whole when it sets a secret literal (next rule).
- Script secret policy: no shell is parsed for secrets. Script text (`script`/`bash`/`pwsh`/`powershell` steps and every task input string, for example the `script`, `inlineScript` and `arguments` inputs of Bash@3, PowerShell@2 and CmdLine@2) is scanned, including comment-looking lines and heredocs, for `##vso[` logging commands. If any command sets a secret (`task.setsecret`, or `task.setvariable` with `issecret=true`, [Logging commands](https://learn.microsoft.com/en-us/azure/devops/pipelines/scripts/logging-commands) document `SetSecret` and `isSecret`) and its payload (rest of the line up to the next command) is not provably only a single reference (`$(macro)`, `$VAR`, `${VAR}`, `$env:VAR` or `%VAR%`), the whole text is replaced by `[REDACTED]`, the node gets a `needs-manual` loss ("secret literal in script: supply it from a secret store and restore the script manually") and the operation carries a `SecretRef`. VERIFY: matching `##vso[` case-insensitively is a conservative choice; the agent's real case sensitivity is not confirmed.
- Secret scope decision (maintainer, fix6; it refines [IR rule 7](ir.md)). GUARANTEED: values of declared secrets never reach the IR, extensions or diagnostics: secret variables, `issecret=true` / `task.setsecret` payloads, secret parameters, secret-classified keys, URL userinfo and the built-in credential patterns of `internal/redact`. The guarantee is per value class. (1) Long values (non-numeric, not bool-like, 4 or more bytes after the literal predicate): every occurrence anywhere in a string leaf, including inside longer text, plus the lower-case, upper-case and JSON-escaped forms. (2) Numeric values (decimal shape, including negative, fractional and zero-padded forms) of 6 or more characters: the same as long values, a deliberate loss that also redacts that digit run inside unrelated text such as `echo 123456`. (3) Short values (under 4 bytes) and numeric values under 6 characters: only a string leaf that equals the value (or its trimmed form) is replaced; the value embedded in longer text (`echo 12345`, a container option, a demand, an opaque condition) is NOT replaced, an accepted limit because such a short digit run cannot be told from ordinary text. A script, opaque condition or string literal that references such a variable by name (`$(name)`, `variables.name`, `variables['name']`) gets a `needs-manual` loss (`shortSecretReference`) carrying only the variable name, and the reference text is left intact (no broadened replacement); a condition the portable expression AST keeps structured is flagged the same way. (4) Bool-like values (`true`/`false`, any case): whole string leaves only, and a bool-like secret that reaches a typed boolean carrier (a literal boolean in a condition, `continueOnError`, `persistCredentials`, `submodules`) is converted by the resolver to a boolean, so it cannot be recognised there; this is an unavoidable limit. For every decimal-shaped value the canonical spelling the expression lexer produces (leading zeros, trailing fractional zeros, trailing dot and negative zero removed, leading zero added: `007421` becomes `7421`, `1.50` becomes `1.5`, `.5` becomes `0.5`) is tracked as well, so a number literal built from the value is replaced; a canonical form of fewer than 6 characters (for example `1` or `0`) is whole-leaf only, so it also replaces an unrelated number literal with that text. Exponent forms (`1.0E+10`) are tracked as written and, at 6 or more characters, also replaced inside longer text; no canonical rewriting is applied to them. BEST EFFORT (heuristic, with the documented limits below, `needs-manual` when detected): secret-looking literals inside free-form text. An undetected free-form literal is a documented limit, not a defect. Future reviews block only on (a) a leak of a declared secret, (b) a crash, panic or resource exhaustion, (c) silent semantic corruption.
- IR-wide backstop: after normalization every string leaf of the IR (extensions, raw nodes, typed trigger details, conditions, display names, container options) is passed through the redact scrubber, and `KEY=value` pairs with a secret-classified key in every free-form leaf except script bodies lose their value. In task inputs and container options, whitespace flags with a secret-classified name (`--client-secret X`, `--password X`, `--token X`, `--secret X`, `--api-key X`, `-Password X`) lose their value, and a pool demand `NAME -equals VALUE` with a secret-classified `NAME` loses `VALUE`. Scripts follow the whole-text policy above instead. The scanner is an iterative single pass (linear work, no recursion); a leaf above 1 MiB is replaced as a whole by the placeholder (`needs-manual`). When a condition compares a secret-classified variable path with a non-reference literal (`eq(variables.DB_PASSWORD, 'x')`) the literal is replaced and the node is `needs-manual`; opaque conditions get the same conservative scan (every quoted non-reference literal is replaced when the text names a secret-classified variable). Any change records a `needs-manual` loss on the nearest node with metadata and raises the enclosing nodes' fidelity.
- Secret-name exceptions are exact and context-specific, never a blanket suffix rule. Generic `*Credentials` and lowercase `pwd` keys are secret-classified. In task inputs only, `externalFeedCredentials` and `publishFeedCredentials` are service-connection names ([NuGetCommand@2](https://learn.microsoft.com/en-us/azure/devops/pipelines/tasks/reference/nuget-command-v2) and [DotNetCoreCLI@2](https://learn.microsoft.com/en-us/azure/devops/pipelines/tasks/reference/dotnet-core-cli-v2) document both as service-connection inputs); `imagePullSecret`/`imagePullSecrets` contain Kubernetes secret names ([KubernetesManifest@1](https://learn.microsoft.com/en-us/azure/devops/pipelines/tasks/reference/kubernetes-manifest-v1)). `persistCredentials` is parsed as the checkout boolean option, not as a credential value ([checkout schema](https://learn.microsoft.com/en-us/azure/devops/pipelines/yaml-schema/steps-checkout)). VERIFY: uppercase `PWD` is treated as the conventional current-directory environment key, while lowercase `pwd` remains password-like.
- `strategy.parallel` above 256 replicas becomes an opaque matrix; smaller counts expand to legs carrying `System.JobPositionInPhase` and `System.TotalJobsInPhase`. A dynamic matrix expression is not present in the AST, so only a loss is recorded.
- Backstop details: `KEY=value` values are whitespace-delimited and honour quotes (`KEY="a b"`, `"KEY=a b"`); they are never cut at `,`, `]`, `}` or `;`. The value of a non-secret key is scanned again (`--env=DB_PASSWORD=x`). Raw JSON extensions are decoded and re-encoded with order preserved: string leaves are scrubbed, matching number tokens become the JSON string `[REDACTED]`, and every duplicate final object key receives the first unused `-N` suffix within that object. The same reservation-aware allocator repairs ordered-map keys and ID namespaces after scrubbing, including partial replacements such as `prefix[REDACTED]`; every repair records a `needs-manual` loss. Structural `construct`, `property` and `detail` keys of extension loss objects are never tainted. Any string leaf that sets a secret through a logging command (string and `stepList` parameter defaults, `templateContext`, `unknown.*` keys) is replaced as a whole. Matrix leg values and task `arguments` / `args` / `options` entries are scrubbed like other keyed literals.
- Known limits of static secret detection (all deliberate):
  - Shell obfuscation cannot be detected statically: string splicing (`##vso[task.set""secret]x`), `printf` formats, escapes such as `\x23`, and values assigned elsewhere in the script (`PW=x; echo ##vso[task.setsecret]$PW` is treated as a reference).
  - VERIFY: `task.setendpoint` `authParameter` values are not treated as secrets; whether the agent accepts them is unconfirmed.
  - VERIFY: a leading space or NBSP inside `##vso[ task.setsecret]` is not matched; whether the agent tolerates it is unconfirmed.
  - Payloads such as `$(az ...)`, `$($obj.prop)` and `${X:-d}` are not provably a single reference, so the whole script is replaced conservatively and recorded as `needs-manual`.
  - Backstop false positives are accepted and recorded as `needs-manual` losses, for example `?token=$(T)`, `Cookie: none` and `--token value` in an unrelated task input. Line continuations (backslash, caret, backtick) are joined only for the resolved shell of a `bash`/`pwsh`/`powershell` step; for `script:` (Azure default shell), task inputs and non-script leaves all three are joined, a conservative false positive recorded as `needs-manual` (pinned by tests). Normal URLs, `git@` and `ssh://` remotes, `@scope/pkg`, `LOG_LEVEL=debug`, `TOKEN_ENDPOINT=...` and `KEY=$(x)` pass through unchanged (pinned by tests).
  - Work bounds (resource exhaustion, deliberate): the value predicates of a secret-classified key run once per key on a bounded value. A value longer than 4 KiB is treated as a secret literal without the boolean/number/reference/deferred tests (so a long value containing `$(` is replaced), and numbers longer than 256 bytes are ordinary values. The `$(` search is shared by every key of the same token. Each free-form leaf has a work budget of `16 * len + 256` steps (lexer, whitespace search and predicates all count); when it is exceeded the whole leaf is replaced by the redaction placeholder with a `needs-manual` loss. Leaves above 1 MiB are replaced as before. For scripts, the quote and comment state of a line is carried forward between `##vso[` commands (one pass) and a per-script bound of the same shape replaces the whole script with the placeholder and a `needs-manual` loss. Tests assert the bounds through work counters and replacer scan counters, not wall-clock time.
- Secret propagation (root declarations): the resolver substitutes parameter and variable literals into every use site (`env`, scripts, task inputs, display names). The normalizer therefore collects every non-empty literal value of secret-classified ROOT parameters (defaults, including nested leaves under a secret-classified key of an object default, in list and map form) and root variables (map and list form), and the backstop replaces every occurrence of those values in every string leaf, script bodies and display names included, with the placeholder; each change records a `needs-manual` loss on the nearest node. All declared values, including boolean-like, numeric and short forms, are registered for whole-leaf replacement; surrounding-whitespace declarations register both the source and trimmed forms so typed conversions cannot escape. Components the normalizer composes into a longer string (the `!` exclude-glob prefix, `<stage>.<job>` job identifiers and `needs`, `unknown.<key>` extension keys, trigger identifiers built from resource names, step identifiers before `-N` suffixes, the `service.<key>` and `matrix.<key>` extension keys and loss properties) are passed through the replacer BEFORE they are composed, and distinct replaced components keep distinct spellings per namespace (`[REDACTED]`, `[REDACTED]-2`, allocated in first-use order; stage spellings are claimed in stage order so job prefixes follow the stage IDs), so a composite never hides a whole-leaf secret. Every such replacement records a `secretMaterial` `needs-manual` loss on the node that owns the composite (for a `<stage>.<job>` identifier also on the stage that lists it). Spelling allocation is linear in the number of distinct components. When a declaration spelling is ambiguous (the same ID declared twice) no reference is re-pointed to either declaration. Values of at least 4 bytes that pass the literal predicate, and decimal values (and their canonical forms) of at least 6 characters, additionally go into one substring replacer built once (linear in the leaf bytes plus the literal bytes), longest first; replaced text is never scanned again, so placeholders never nest. Besides the literal, its lower-case, upper-case and JSON-escaped (with and without HTML escaping) forms are replaced, which covers `lower()`, `upper()` and `convertToJson()` of a parameter. Other compile-time transforms (`replace()`, `format()` splits, substring or `join()` results, base64) produce text that is not derived by these rules and are a known limit. Whole-leaf forms are never replaced inside longer text. The total size of tracked literals is bounded (48 KiB); beyond it every eligible string leaf is replaced by the placeholder with a diagnostic, never left in clear. Plain-string structural fields (run step shell, deployment strategy and hook, runner OS and architecture, annotation level, action and raw provider tags) are never tainted. Dependency, job, scope and output references follow the declaration they named when colliding IDs are de-duplicated. Structural fields are excluded from the pass: enum-typed fields (phase, kind, type and similar) and number literal text are never changed, so a secret default such as `runtime` or `compile` cannot corrupt the IR. Free-text and ID fields are replaced, which visibly over-replaces when a secret equals ordinary text (a secret `postgres` also redacts a `postgres:15` image, `needs-manual`); IDs that collapse to the same text are de-duplicated again with `-N` suffixes so validation holds. User-derived text in findings (property, construct and detail, for example an unknown key name or `matrix.<key>`) is passed through the same replacer and the credential scrubber before the finding or loss is built. Known limit pending resolver taint support (follow-up): values of template-file parameters and call-site parameters (non-root) that were substituted by the resolver are not tracked.
- Numeric and structural exceptions: every source-string-to-integer conversion uses one checked parser that tests the untrimmed and trimmed source text against declared-secret taint first. A match is omitted or replaced atomically, records a `needs-manual` loss, and is never converted to a duration, count, logging-command line/column or replica expansion. A number literal or raw-JSON number token whose text matches a tracked whole-leaf secret (or any tracked secret) is replaced as a whole by the string literal `[REDACTED]` (never edited in part), with a `needs-manual` loss; a number-typed input whose default is redacted this way becomes a string input so the IR stays valid. The `self` / `none` repository written by the normalizer for a checkout is not tainted (a user-written repository alias still is). Any ordered-map key (env, with, permissions) that collides after scrubbing is de-duplicated with the first suffix not already present in that map, with a `needs-manual` loss so the canonical IR stays valid.
  - ID collisions and free text: after colliding IDs are de-duplicated, references inside free text (opaque conditions such as `dependencies.[REDACTED].result`, `$[ dependencies.X.outputs[...] ]` strings, `succeeded('[REDACTED]')`) cannot be re-pointed to the declaration they named and stay ambiguous. Every script, opaque condition and expression string literal that names a renamed declaration (by its original or scrubbed spelling) gets a `needs-manual` loss (`renamedReference`) so the reference is reviewed by hand; a reference the portable expression AST keeps structured (`variables.x` after parsing) follows the declaration and is not re-flagged. The `renamedReference` detail names no ID and carries no secret material; the source position identifies the node, because a short, small-numeric or boolean-like secret value can survive scrubbing inside an ID spelling.
  - Free-text reference scan (#12/#13) is a heuristic and bounded: it searches only the stage, job and step namespaces for the renamed spelling of a colliding ID and the declared short-secret variable names, in scripts, opaque conditions and expression string literals; a leaf above 1 MiB is not scanned and the `needles x text` cost is charged to the work counter. A component collapsed by the credential or `KEY=value` scrubber (so the collision is not predicted), the kept spelling of a colliding pair, the `trigger`, `matrix`, `service` and glob namespaces, and unquoted index forms such as `variables[ name ]` can be missed; a long decimal spelling that canonicalizes below 6 characters (for example `1.000000` to `1`) is flagged as `shortSecretReference` even though its written spelling is replaced inside text (a needs-manual false positive).
  - Origins: `OriginalTextHash` is the SHA-256 of the exact source span. When the source text is unavailable it is the tag `unavailable`; a placeholder is never hashed.
  - Empty or null conditions (`condition: ''`, null, or a parameter that resolved to empty) are absent: no raw node, and a deployment hook gate is applied as for a step without a condition. An empty `container:` is no container; a null container alias is an unresolved alias (loss), never the image `null`.
  - Runtime `$[ ]` whole-scalar insertions for matrix and container are deferred by the resolver and appear in the IR as runtime expressions.
  - Not detected yet (follow-ups): flag forms `--password:X`, `/password X` and a flag value on the next line; `KEY = value` with spaces around `=`; flag scanning is limited to `options`, `args` and `arguments` keys; condition comparisons built through `format()`, macros or `dependencies` outputs; values containing `$(` are not treated as secrets (all-digit values are, as whole-leaf matches only, see above); `curl -u user:password` in scripts; line-continuation joining for `script:`, `cmd` and task scripts beyond the resolved-shell rule above.
