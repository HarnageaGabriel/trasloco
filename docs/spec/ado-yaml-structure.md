# Azure Pipelines YAML structure

Status: draft for approval (M1 wave 2). Normative.

This specification defines how an Azure Pipelines YAML file is read into a typed, position-carrying syntax tree **without expanding templates**, and how that tree is printed back. It is the second stage of the compiler (`parse -> resolve -> normalize`): `internal/yamlx` reads text into nodes, `internal/dialect/azurepipelines/parse` builds the tree of `internal/dialect/azurepipelines/ast`, `internal/dialect/azurepipelines/printer` renders it, and the template resolver (M1 wave 3) consumes it. Expressions are the business of `internal/dialect/azurepipelines/expr` (`ado-expressions.md`); this document only says where they are found and how their positions are mapped.

Keywords MUST, MUST NOT, SHOULD and MAY are used as in `README.md`. A statement prefixed `VERIFY:` is a platform fact that is not confirmed by the cited page; implementations treat it as the documented behavior until it is confirmed (CONVENTIONS.md, "AI agent rules").

## 1. Sources

Every structural rule below cites the page of the official schema reference it comes from. `S:<page>` stands for `https://learn.microsoft.com/en-us/azure/devops/pipelines/yaml-schema/<page>` and `P:<page>` for `https://learn.microsoft.com/en-us/azure/devops/pipelines/process/<page>`. Pages were read on 2026-10-07 for the `azure-pipelines` moniker (Azure DevOps Services). Properties that exist only for newer service versions are accepted unconditionally; version gating is not a structural concern.

## 2. General reading rules

1. **Scalars (ADR 0009).** Every scalar is read through `yamlx.Node.Scalar()`: its value is the decoded text whatever the YAML tag (`60`, `true`, `1.0` and `'60'` are all the string `60`/`true`/`1.0`/`60`). A scalar written as null, `~` or left empty keeps `Null = true`. Typed accessors such as `Bool()` are never used. Fields the schema declares boolean are checked textually (section 2.5).
2. **Anchors and aliases (ADR 0009).** An anchor (`&a`), an alias (`*a`) and a merge key (`<<`) are errors: `TRL-PARSE-0008` and `TRL-PARSE-0009` at the position of the offending node. `parse.Source` enforces this through the yamlx anchor policy; `parse.Document` additionally reports every alias it reaches. The tree is still built from the resolved values so that later findings are not hidden.
3. **Positions (ADR 0003).** Every node carries a `diag.Source` taken from yamlx: `Line`/`Col` are one-based and point at the first character of the node as written (for a quoted scalar, the opening quote; for a block scalar, the `|` or `>` indicator; for a sequence item, the first character after `- `; for a mapping, its first key). `EndLine`, `EndCol`, `Offset` and `EndOffset` are filled by yamlx. A diagnostic about a missing key points at the mapping, about an unknown or duplicate key at the key, about a value at the value.
4. **Ordering (ADR 0005).** Source order is preserved in every list, mapping (`ast.Map`, `ast.Any`, task `inputs`, `env`, `variables`, matrix legs) and in `Extra`. No Go map is iterated on any output path. Diagnostics are added to a `*diag.Collector`, which sorts them by file, line, column and code.
5. **Booleans and enums.** A field the schema declares `boolean` accepts `true` or `false` in any letter case. A field with a closed value set (parameter `type`, `lockBehavior`, stage `trigger`, `workspace.clean`, `target.commands`, repository `type`) accepts the listed values in any letter case; `Canon` holds the canonical spelling. Any other value that is not a template expression or a macro `$(...)` is `TRL-PARSE-0012` at the value. A value that contains a template expression or a macro is only known later and is not checked.
6. **Case-insensitivity.** Mapping keys are matched case-insensitively (`Steps:`, `steps:` and `STEPS:` are the same key); the printer writes the canonical spelling. Two keys of one mapping that are equal ignoring case are `TRL-PARSE-0003` at the second key, and the first wins. Keys that are not defined by the schema keep the case they were written in. VERIFY: the schema pages do not state whether keys and enumerated values are case-insensitive (P:expressions only states it for literals, functions and string comparison). The rule is the working assumption of this specification; if the service turns out to be case-sensitive it is removed here and in `parse`.
7. **Unknown keys.** A key the schema does not define for a node is **never dropped**: it is preserved in the node's `Extra` list (key scalar and free-form `Any` value, in source order) and reported as warning `TRL-PARSE-0002` at the key. A *dynamic* key (a key containing `${{ }}`, such as `${{ pair.key }}: ${{ pair.value }}`) is preserved the same way and is not reported, because only the resolver can know it.
8. **Nesting.** Nesting deeper than the yamlx depth limit (1000) is `TRL-PARSE-0010`; the parser does not descend further.
9. **Multiple documents.** A file holds one document. A second document is `TRL-PARSE-0006` at its root; only the first is parsed. An empty file (or only comments) is an empty pipeline of shape `none` and is not an error.
10. **Shape errors.** A value of the wrong YAML kind (a sequence where a mapping is required, a mapping where a scalar is required, a non-scalar key) is `TRL-PARSE-0006` at the value, naming the key.

## 3. Template directives and expressions

Nothing in this stage evaluates anything. The tree keeps what the resolver needs.

- **Key directives.** A mapping key whose text is `${{ if <expr> }}`, `${{ elseif <expr> }}`, `${{ else }}` or `${{ each <name> in <expr> }}` (source: P:expressions, "Conditional insertion" and "Each keyword") is a *directive entry*. It is kept as an `ast.Directive` with `Kind` (`if`, `elseif`, `else`, `each`), `Raw` (the key text), `Variable` (each) and `Expr` (the parsed condition or iterable). The value of the entry is the directive *body*. Directive keywords are lower-case (VERIFY: the expression engine documents function names as case-insensitive; the directive keywords are matched as the `expr` package does, exactly).
- **Where bodies live.** In a typed mapping node (a job, a step, a pool, ...) directive entries are `Inserts []*Branch[*Self]`: the body is parsed as a partial node of the same type. In a list, a mapping item whose keys are all directive keys becomes one list item per key (`ListItem.Cond`): the body is a list of items of the list's type, or, when the body is not a sequence, a free-form `Any` (as in `- ${{ each pair in step }}:` followed by a mapping). In a mapping of values (`variables`, `inputs`, `env`, `parameters`, matrix) a directive entry is a `MapEntry.Cond` whose body is a mapping of the same kind. In free-form values (`Any`) it is an `AnyEntry` with `Directive` set.
- **Chains.** `elseif` and `else` must directly follow an `if` or `elseif` in the same list or mapping; an ordinary item or entry in between breaks the chain. Otherwise `TRL-PARSE-0013` at the directive. A directive without a body (`${{ if x }}:` followed by nothing) is also `TRL-PARSE-0013`. A directive whose head cannot be parsed is `TRL-EXPR-0001` at the offending column; the body is still kept.
- **Value directives.** A `${{ expr }}` occurrence inside a scalar (a value or a dynamic key) is an `ast.Directive` of kind `insert` in `Scalar.Directives`, with `Start`/`End` offsets inside the scalar value and the parsed `Expr`. A scalar that is exactly one `${{ }}` (or exactly one `$[ ]` runtime expression, kind `runtime`) is a *whole-value* directive (`Scalar.Whole()`). Where a compound node is expected (`steps`, `pool`, `strategy`, `matrix`, `variables`, `resources`, ...), a whole-value directive stands for the structure: the node has `Insertion` set and no other fields. In a list, a scalar item that is a whole-value directive is `ListItem.Insert` (it can expand to any number of items). An unterminated `${{` is `TRL-EXPR-0001` at the `${{`.
- **Expression-valued fields.** `condition` of stages, jobs, deployments and steps is an `ast.Expression`: the raw text stays in `Value` and the text is parsed with `expr.Parse`; `Expr` is the AST. A condition that contains a template expression (`eq(${{ parameters.a }}, 'x')`) is not parsed (`Expr` is nil, the `${{ }}` occurrences are in `Directives`) because it is only an expression after expansion. A syntax error is `TRL-EXPR-0001`.
- **Spans.** `expr` returns byte offsets relative to its input. The parser maps every node span back to the file through `yamlx.ScalarMapper`, which knows plain, single-quoted, double-quoted, folded and literal scalars, and stores the result in `ExprSources` (`Expression`, `Directive`). Each entry pairs the span exactly as `expr` reports it (`Range()` of the node) with the file source, whose end is one past the last character of the node and stays on that character's line in folded and block scalars. For an `Expression` the spans are relative to `Value`, for an inserted or runtime `Directive` to its `Raw`, for an `if`/`elseif`/`each` key to the expression text after the keyword: `expr.ParseDirective` reports those spans relative to the expression, not to the key (reported as an inconsistency, `expr` is not changed). Syntax errors are reported at the mapped position of the error offset: in `condition: "and(succeeded(), eq(1,))"` the unexpected `)` is reported at its own column inside the quotes, and in a folded scalar at the line and column where that character was written.

## 4. Pipeline

Source: S:pipeline. A file is one mapping with the pipeline-level properties of section 4.1 and at most one *shape* key.

|---|---|---|

| `pr` | `none` \| list of branches \| object (section 5) | S:pr |

### 4.2 Shapes

Exactly one of the following keys selects the shape; `shape` is `none` when none is present (a variables or parameters template file).

| Key | Shape | Content | Source |
|---|---|---|---|
| `stages` | `stages` | list of stages and stage templates (section 10) | S:pipeline "pipeline: stages", S:stages |
| `jobs` | `jobs` | list of jobs, deployments and job templates; one implicit stage | S:pipeline "pipeline: jobs" |
| `steps` | `steps` | list of steps; one implicit stage and job. The job properties `strategy`, `continueOnError`, `pool`, `container`, `services` and `workspace` may appear next to it | S:pipeline "pipeline: steps" |

A second shape key is `TRL-PARSE-0014` at that key; both are still parsed. Template files use the same node types: a steps template is a `steps` shape with `parameters`, a variables template has shape `none` (P:templates "Variable reuse").

## 5. Triggers, pull requests and schedules

- `trigger` (S:trigger) and `pr` (S:pr) are one node, `ast.Trigger`, with `Form`:
  - `none`: the scalar `none` (any case). `Keyword` keeps the scalar.
  - `list`: a sequence of branch names, equal to `branches.include`. The tree stores it as `Branches` with `Bare = true`.
  - `full`: an object. For `trigger`: `batch`, `branches`, `paths`, `tags`. For `pr`: `autoCancel`, `branches`, `paths`, `drafts`. A key valid only for the other one (`batch` under `pr`) is an unknown key (section 2.7). An empty value (`trigger:`) is `full` without fields. VERIFY: behavior of a null trigger.
  - `insertion`: a whole-value `${{ }}`.
  - Any other scalar is `TRL-PARSE-0012` (allowed: `none`).
- `branches`, `paths`, `tags` are filters (S:include-exclude-filters): an object with `include` and `exclude` lists of strings, or a bare list. VERIFY: the bare list is documented for the pipeline-resource trigger (S:resources-pipelines-pipeline-trigger) only; it is accepted for every filter.
- `schedules` (S:schedules-cron): a list of objects with `cron` (required, `TRL-PARSE-0011` when missing), `displayName`, `branches` (filter), `batch`, `always` (boolean).

| `pipelines` | `pipeline` | `pipeline`, `project`, `source`, `version`, `branch`, `tags` (list), `trigger` (resource trigger) | `pipeline` | S:resources-pipelines-pipeline |
| `containers` | `container` | `container`, `image`, `type`, `trigger` (resource trigger), `azureSubscription`, `resourceGroup`, `registry`, `repository`, `localImage` (boolean), `endpoint`, `env` (mapping), `mapDockerSocket` (boolean), `options`, `ports`, `volumes` (lists), `mountReadOnly` (`work`, `externals`, `tools`, `tasks`: boolean) | `container`, `image` | S:resources-containers-container |
| `builds` | `build` | `build`, `type`, `connection`, `source`, `version`, `branch`, `trigger` (`none` or `true`) | `build`, `type`, `connection`, `source` | S:resources-builds-build |

Any other scalar is `TRL-PARSE-0012`. VERIFY: the webhook filter item keys `path` and `value` are not shown on S:resources-webhooks-webhook-filters; they are accepted and unknown keys are preserved.

## 7. Parameters

Source: S:parameters-parameter, P:templates. `parameters` is a list of objects with `name` (required), `displayName`, `type`, `default` (any value, kept as a free-form tree) and `values` (list of strings). `type` is one of `string`, `number`, `boolean`, `object`, `step`, `stepList`, `job`, `jobList`, `deployment`, `deploymentList`, `stage`, `stageList` (S:parameters-parameter "Types"); `stringList` is accepted too (VERIFY: not in that table). A `type` outside the set is `TRL-PARSE-0012`; an omitted `type` is allowed (VERIFY: the page requires it, but its own template examples omit it). A parameter `default` may contain directives and dynamic keys; they are preserved. The legacy mapping form (`parameters:` followed by `name: default` pairs, shown on S:stages-template) is accepted and kept as `ParametersMap`. A whole-value `${{ }}` is `ParametersInsertion`.

## 8. Variables

Source: S:variables. Two forms, never mixed in one block (S:variables "Remarks"):

- **Mapping**: `name: value` pairs, `Form = map`, an ordered `ast.Map` of scalars. Directive entries are allowed (P:expressions "Conditionally assign a variable"). A value may be a macro, a template expression or a `$[ ]` runtime expression; these are kept as scalar directives.
- **List**: items that each have exactly one of `name` (S:variables-name: `name`, `value`, `readonly`), `group` (S:variables-group) or `template` (S:variables-template: `template`, `parameters`). No such key is `TRL-PARSE-0011`; more than one is `TRL-PARSE-0014` (the first, in source order, selects the item and the others are unknown keys).

A whole-value `${{ }}` is `Form = insertion`. Variables may be declared at pipeline, stage and job level.

## 9. Pool, container, workspace and friends

- **Pool** (S:pool). `pool: name` is the short form (`Short = true`, `Name`). The object form has `name`, `demands` (a string or a list of strings; `DemandsScalar` records the string form) and `vmImage`. `pool: server` is the pool name `server` (S:jobs-deployment-strategy, canary example). Pools appear on the pipeline, stages, jobs, deployments and lifecycle hooks.
- **Container** (S:jobs-job-container). A string is an alias (a container resource name or an image). The object form has `image`, `endpoint`, `env`, `mapDockerSocket`, `options`, `ports`, `volumes`, `mountReadOnly`. A whole-value `${{ }}` or `$[ ]` is an insertion (`container: $[ variables['x'] ]`).
- **services** (S:jobs-job): a mapping of names to container aliases.
- **workspace** (S:workspace): `clean` is `outputs`, `resources` or `all`.
- **uses** (S:jobs-job-uses): `repositories` and `pools`, lists of strings.
- **dependsOn** (S:stages-stage, S:jobs-job): a string or a list of strings; `dependsOn: []` is an explicit empty dependency list and is kept (`Names` is empty, not nil).
- **target** (S:target): a string (`Short`) or an object with `container`, `commands` (`any`, `restricted`) and `settableVariables` (`none` or a list of names).

## 10. Stages

Source: S:stages, S:stages-stage, S:stages-template. Each item has `stage` (a stage) or `template` (a stage template); none is `TRL-PARSE-0011`, both is `TRL-PARSE-0014`.

`stage` keys: `stage` (id), `group`, `displayName`, `pool`, `dependsOn`, `condition` (expression), `variables`, `jobs`, `lockBehavior` (`sequential`, `runLatest`), `trigger` (`manual`, `automatic`), `isSkippable` (boolean), `templateContext` (free-form). A stage template has `template` and `parameters` (S:stages-template).

## 11. Jobs, deployments and strategies

Source: S:jobs-job, S:jobs-deployment, S:jobs-template. Each item has `job`, `deployment` or `template`; none is `TRL-PARSE-0011`, several is `TRL-PARSE-0014`. The id of a template-style job may be empty (`- job:`), as in P:templates "Reuse jobs".

- **job** keys: `job`, `displayName`, `dependsOn`, `condition`, `continueOnError`, `timeoutInMinutes`, `cancelTimeoutInMinutes`, `variables`, `strategy`, `pool`, `container`, `services`, `workspace`, `uses`, `steps`, `templateContext`.
- **strategy** of a job (S:jobs-job-strategy): `matrix` (mapping of leg name to mapping of variable to value; a whole-value `${{ }}` is allowed) with `maxParallel`, or `parallel`. Matrix legs keep source order.
- **deployment** keys: `deployment`, `displayName`, `dependsOn`, `condition`, `continueOnError`, `timeoutInMinutes`, `cancelTimeoutInMinutes`, `variables`, `pool`, `environment`, `strategy`, `workspace`, `uses`, `container`, `services`, `templateContext`.
- **environment** (S:jobs-deployment-environment): a string (`name` or `name.resource`, kept whole, `Short = true`) or an object with `name`, `resourceName`, `resourceId`, `resourceType`, `tags`.
- **deployment strategy** (S:jobs-deployment-strategy and its `runOnce`, `rolling`, `canary` pages): an object with `runOnce`, `rolling` or `canary`. Each is a lifecycle with `preDeploy`, `deploy`, `routeTraffic`, `postRouteTraffic` hooks and `on.failure` / `on.success`; a hook has `steps` and `pool` (S:deploy-hook). `rolling` also has `maxParallel` and `canary` has `increments` (list). Which of the three is present is not validated beyond that.
- **template** (S:jobs-template): `template` and `parameters`.

## 12. Steps

Source: S:steps and the pages listed below. Each item is a mapping whose *keyword key* selects the kind (the schema requires it first; here it may appear anywhere). No keyword is `TRL-PARSE-0011`, more than one is `TRL-PARSE-0014`; the first in source order selects the kind and the other keys are reported as unknown.

| Keyword | Kind (`ast`) | Own keys | Source |
|---|---|---|---|
| `script`, `bash` | `ScriptStep` | `failOnStderr`, `workingDirectory` | S:steps-script, S:steps-bash |
| `pwsh`, `powershell` | `ScriptStep` | `errorActionPreference`, `failOnStderr`, `ignoreLASTEXITCODE`, `workingDirectory` | S:steps-pwsh, S:steps-powershell |
| `task` | `TaskStep` | `inputs` | S:steps-task |
| `checkout` | `CheckoutStep` | `clean` (boolean), `fetchDepth`, `fetchFilter`, `fetchTags`, `lfs`, `persistCredentials`, `submodules`, `path`, `sparseCheckoutDirectories`, `sparseCheckoutPatterns`, `workspaceRepo` | S:steps-checkout |
| `download` | `DownloadStep` | `artifact`, `patterns` | S:steps-download |
| `downloadBuild` | `DownloadBuildStep` | `artifact`, `path`, `patterns` | S:steps-download-build |
| `getPackage` | `GetPackageStep` | `path` | S:steps-get-package |
| `publish` | `PublishStep` | `artifact` | S:steps-publish |
| `reviewApp` | `ReviewAppStep` | (none) | S:steps-review-app |
| `template` | `StepTemplate` | `parameters` (no common properties) | S:steps-template |

All kinds except `template` share the common properties `name`, `displayName`, `condition` (expression), `continueOnError` (boolean), `enabled` (boolean), `env` (mapping), `timeoutInMinutes`, `retryCountOnTaskFailure` and `target` (section 9) (S:steps-task and the pages above). The values of `timeoutInMinutes`, `retryCountOnTaskFailure`, `fetchDepth`, `fetchTags`, `lfs`, `persistCredentials` and `submodules` are scalars, not checked as booleans or numbers, because the pages declare them string.

**Task references** (P:tasks "Task versions" and "Custom tasks"). `task: Name@Version` or `task: GUID@Version`; `Version` is a major version (`2`) or a full version (`0.3.1`). The parsed `ast.TaskRef` has `Name`, `IsGUID` (a task GUID in 8-4-4-4-12 hexadecimal form), `Version` (as written), `Major` (-1 when unknown), `Dynamic` and `Valid`. A reference without `@`, with an empty name or version, with white space, or with a version that is not one to three dot-separated numbers is `TRL-PARSE-0015` at the value (the name is still kept). VERIFY: a missing version is an error in the service ("you must specify the major version"), and the grammar of the version text beyond P:tasks is not documented. A reference containing a template expression or a macro is `Dynamic` and not checked. Task `inputs` are an ordered `ast.Map` of scalars (source order, ADR 0005); input aliases are **not** resolved here.

## 13. Template references and extends

Source: S:extends, S:steps-template, S:stages-template, S:jobs-template, S:variables-template, P:templates "Reference template paths". A template reference has `template` (path) and `parameters` (an ordered mapping of free-form values, directives allowed). The path is split at the last `@`: `File` is the path and `Alias` the repository resource alias (`@self` for the current repository, P:templates "Store templates in other repositories"); a path containing a template expression is `Dynamic` and kept whole. `extends` (S:extends) has the same two keys. Cross-repository resolution is the resolver's concern.

## 15. Printer

`printer.Print` renders the tree as normalized YAML: canonical key spelling and order (the order of the tables above), two-space indentation, LF line endings, no comments. Scalars are written from their decoded text with the tag left implicit, so numbers and booleans stay unquoted and text that would read back as another type is quoted; directive keys and values are written from their raw text. Unknown keys follow the typed fields, then the key directives. The output is passed through `yamlx.Parse` and `yamlx.Emit(Normalize)` (ADR 0009). The property `parse -> print -> parse` is the identity on the tree ignoring positions; it is tested over every vector, every file of `testdata/azurepipelines/structure/` and by fuzzing. Not preserved: comments, the original order of directive entries relative to typed fields of the same mapping, quoting style, the original case of keys.

## 16. Open points (VERIFY)

1. Case-insensitive keys and enumerated values (section 2.6).
2. Directive keywords are matched exactly (`if`, `elseif`, `else`, `each`) (section 3).
3. Parameter type `stringList`; omitted parameter `type` (section 7).
4. Behavior of a null `trigger` / `pr` (section 5).
5. Bare-list filters outside the pipeline-resource trigger (section 5).
6. Webhook filter keys (section 6).
7. Missing task version is an error; grammar of the version text (section 12).
8. Whole-value `${{ }}` accepted wherever a compound value is expected (section 3).
9. Null values for list- and mapping-valued keys are accepted as empty.
10. `continueOnError`/`enabled` and other boolean fields do not accept YAML 1.1 spellings (`yes`, `on`).
